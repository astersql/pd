## 实现与 oracle

新增 `region_rule_cache.rs`、独立 `placement_cache_test.rs` 与 lib 显式登记；
RuleManager 持有唯一缓存。公开入口和 host 序列化契约见
[模块说明](../../../../pkg/schedule/placement/region_rule_cache.rs.md)。
缓存候选与 bestFit 分离：首次 Set 为 0 次，随后第 10 次 Set 才提升结果。
RuleManager 首次缓存插入由调用方显式请求，只有 unchanged candidate 才在 Fit 中提升，
与 Go FitRegion 的 isCached 分支相同。disabled 时绕过查找和提升。
无缓存及缓存计算均使用真实 canonical core、规则、范围规则查询与 fit 搜索。

[原始运行输出](task29/go.out)验证既有 Go 测试内的断言，不宣称导出了新的 JSON oracle。
`TestRegionRuleFitCache` 固定 unchanged=true；leader/epoch/conf_ver、down peers、
规则 group/id/version/create timestamp/增删及无 heartbeat/空 store 改变为 false。
peer topology 按 Go epoch 契约推进 conf_ver，不额外添加未经 Go 支持的 raw-peer 相等条件。
`TestToStoreCacheListDoesNotReinsertStaleStore` 与
`TestToStoreCacheListReturnsUncacheableForRemovedStore` 固定 removed 当前 store
不允许旧快照插入；`TestSetCacheDoesNotPromoteStaleFitAfterStoreRemoval` 固定不提升；
`TestSetCachePromotionCannotRaceStoreRemoval` 固定 promotion 后收到 removal 必须逐出。
`TestPublicStoreCaches` 的共享指针是 Go 内部优化，Rust 不提供内部指针身份 API。
Rust 以不可变 Arc 快照及 remove-store 扫描实现相同淘汰，不引入第二个 mutable store 表。
