## 实现与行为依据

[gc.rs](../../../../pkg/schedule/labeler/gc.rs) 与
[模块说明](../../../../pkg/schedule/labeler/gc.rs.md) 记录公共符号：
`RegionLabeler::{clear_expired_labels,get_rule_and_key_range_counts}`、
`LabelerGc::{start,shutdown}`、`LabelerMetrics::register`。
lib.rs 显式注册独立测试；Cargo 复用集中 Tokio 和 prometheus 依赖。

只读 Go oracle：labeler.go doGC/checkAndClearExpiredLabels（70–112 行）、
GetRuleAndKeyRangeCounts（207 行起）、rules.go 的严格 Before 判断，
以及 labeler_test.go TestGC/TestLabelerRuleTTL/TestExpiredRuleRemovalPublishesRangeIndex。
输入为 1 秒 TTL、永久标签、相同范围的完全/部分过期规则；到期瞬间仍保留，
超过到期后清除，空规则删除，非空规则逐条保存。存储错误保留内存清理并继续；
Go map 遍历次序无契约，Rust 稳定按 ID 处理，错误顺序不作跨语言比较。
计数忽略全过期规则，部分过期仍统计全部原范围。GC 事务没有整体原子性。

metrics.go 的 counter 名称、help、类型、type/event labels，以及 histogram 名称、
help、类型和 0.001*2^n（n=0..12）桶均保留。宿主 Registry 显式注册，重复注册
返回错误，部分失败回滚。原 Go rule_count/range_count gauge 在 scheduler controller
采样 GetRuleAndKeyRangeCounts；本基础 crate 提供计数而不引入 scheduler 依赖。
原 counter 由 checker/scheduler deny 事件使用，不臆造 GC 事件。宿主负责缓存
counter child、观察创建耗时和 collector 生命周期。
