# Rust 候选的掉电与快照发布回执

实验在 Darwin arm64、macOS 27.0、APFS 本地日志型卷运行。每个节点只使用
私有临时目录中的专用镜像。Rust `sqlite-vfs` 接收实际 bundled SQLite 3.51.3
的写入、截断和同步。同步前的写保存在易失视图。切断时冻结已同步的文件，
之后以默认 SQLite VFS 重开副本。该模型验证同步边界和恢复状态，覆盖范围为
单连接隔离虚拟盘。设备硬件掉电行为需独立验证。
[Rust VFS](../../../pkg/storage/kv/candidate_power_vfs_test.rs)、[模型校准](sqlite-power-evidence.md)。

三节点以真实 OpenRaft 0.9.22 提交两个键。提交时隔离一个跟随者，客户端在收到
revision 1 后独立写入并同步确认日志。切断后的镜像中，原主节点和参与确认的
跟随者有同一日志 ID，隔离节点没有该日志。丢弃原主镜像后，余下两节点重新
选主。通过线性读屏障后，两个键均与确认日志一致。
[多数派对账](../../../pkg/storage/kv/candidate_raft_test.rs)。

快照实验先发布第一笔事务的快照，再提交第二笔。对第二次快照发布注入故障，
在预定边界截断并重开。回收的快照通过版本和 SHA-256 校验，再安装到另一个
空数据库读取完整键值。独立校验还验证破坏校验字段的快照会被拒绝。

| 截断点 | 重开后的快照 | 已应用的业务与日志 |
| --- | --- | --- |
| WAL 短写后 | 第一笔，`T1-N1-2` | 第二笔，`T1-N1-3`，日志未截断 |
| WAL 同步报错后 | 第一笔，`T1-N1-2` | 第二笔，`T1-N1-3`，日志未截断 |
| 新快照发布后 | 第二笔，`T1-N1-3` | 第二笔，日志未截断 |
| 新快照发布并截断日志后 | 第二笔，`T1-N1-3` | 第二笔，截断索引与快照一致 |

额外用例分别注入 WAL 同步失败、空间不足与短写，确认新事务失败，重开后保留
之前已确认的事务。另有真实子进程中止用例，分别在同步前、同步后但确认前及
确认后结束写入进程并重开。同步前没有该记录，后两个场景均找回记录。
进程中止只证明进程恢复边界，设备掉电证明来自上面的 VFS 镜像实验。

`cargo test --offline --locked -p astersql-pd-storage-kv --lib theme10_candidate_ -- --nocapture --test-threads=2`
退出0，7通过、0失败、0忽略，临时子进程入口不计入有效测试数。初次并发运行
发现夹具只切断流向隔离节点的消息，隔离节点仍能发起投票，导致追赶测试换主。
修复双向隔离，并在同主追赶用例中暂停隔离节点选举。换主仍由多数派重开用例覆盖。
