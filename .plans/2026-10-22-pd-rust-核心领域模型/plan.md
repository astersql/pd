# PD Rust 核心领域模型计划

## Go 只读硬约束

- Go 仅供只读参考。禁止新增、修改、删除、重命名任何 `.go` 文件（含生产代码、测试、oracle、生成文件及临时目录中的 Go 工具）；`go.mod`、`go.sum`、`go.work`、`go.work.sum` 同样只读。所有新增实现与测试使用 Rust，必要的非 Go 验证脚本和证据文档须在任务范围内。
- 禁止通过生成器、格式化、依赖整理、failpoint 注入或构建脚本间接改写 Go；不得运行会改写 Go 的 make 测试入口、failpoint 启停命令、`go generate`、`go mod tidy` 或 Go 格式化写入命令。不得以“只增加测试/工具”“临时修改后还原”或扩大任务范围绕过约束。
- Go oracle 仅复用已有只读源码、测试、fixtures、已保存输出或已有二进制；运行已有 Go 工具/测试前，必须确认整个调用链不写上述文件且不需要 failpoint 注入。需要 failpoint 的测试不得直接裸跑来替代验证；无法只读取得必要运行证据时，记录具体缺口并按任务阻塞规则处理，不降低验收标准，不将源码推导冒充运行差分。
- 开始与结束时核对上述文件的 Git 状态及内容，保留用户已有变更；本任务不得产生任何 Go 文件或 Go 模块文件差异。本约束优先于计划、执行技能或验证要求中任何相冲突的写入指令。

目标：把主题 2 分解为单一行为的小任务，逐步提供可被下游依赖的真实 Rust 核心模型与响应转换。

范围：`pkg/core/storelimit`、`pkg/core` 的 Store、Region、树索引、状态容器和 BasicCluster，以及 `pkg/response`；协议转换与阶段追踪放在现有 `pkg/server` 适配层。

范围外：完整调度、集群心跳服务接入、持久化、网络路由切换、全局 Runner 移植和 Go 工厂对象池机械翻译。

假设：规划基准为 `0820f0b67b0e49b289b84fdf66b7b8fb178afe82`。已有 workspace、叶子 crate 和 server/proto，尚无 core、storelimit、response crate；同名叶子能力仍须逐项核验。

## 设计决策

- 比较整包迁移、按文件迁移、按行为拆分；采用行为拆分，独立验证后提交，避免大文件变成大任务。
- 使用 canonical crate；新增模块留在 Go 包旁，协议及指标宿主装配留在 server。

## 架构说明

- `server -> response/core -> storelimit/叶子`；core 禁止 proto、transport、storage 依赖。
- 显式时钟、取消和随机源；不创建私有运行时或全局注册器。

## 开发策略

- Go 源码、测试和模块配置均只读；禁止新增、修改、删除 `.go` 文件，包括 oracle 测试。任务扩围也不得突破此约束。

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前规划失败验证命令和预期失败。
- 将实施步骤限制在失败测试所证明的行为范围内。
- 测试真实行为，不验证模拟对象或实现细节。
- 依赖、线性顺序与批次均以编号任务和 prompt.md 为准。所有批次串行，避免共享 lib.rs、Cargo.lock、格式化及 Go failpoint 改写争用；Cargo 槽位仍与其他计划共用。
- Rust 使用小型 JSON 场景 fixture；期望来自只读 Go 源码和已有测试，逐场景记录符号、断言及推导过程。运行已有 Go 测试留证，区分实际运行覆盖和源码推导场景，不将后者宣称为跨语言运行差分；无法确定预期则阻塞。禁止手抄 Rust 结果冒充 Go 行为依据。浮点仅在明确精度后比较，时间与随机只归一化非业务差异。
- 文档和最终审计不代替行为迁移；未满足依赖必须保留阻塞证据。来源史诗与上层 plan.md 保持原样，只有最终回归任务可按其完成条件关闭来源史诗。
