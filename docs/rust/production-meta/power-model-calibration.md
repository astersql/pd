# 专用镜像掉电模型校验

以 `0325af629150bdd6626cbf928ceb5a0afedb8d17` 为基准，在 Darwin arm64
使用 Python 3.9.6 运行 `python3 docs/rust/production-meta/check_power_model.py`。
退出码 0，3 个校验场景通过，0 失败、0 忽略。重复执行的 JSON 逐字节相同。
[可复跑脚本](check_power_model.py)、[完整输出](power-model-calibration.json)。

脚本仅在新建的私有临时目录内独占创建普通文件。每个镜像为 4 个 512 字节
扇区，操作检查边界，结束后由临时目录机制回收。缓存中的写入在模拟掉电时
被丢弃，FLUSH 把此前完成的写入落盘并同步，FUA 只使当前扇区持久化。
确认日志单独写入镜像之外的文件并同步。对账从新打开的镜像读出字节和摘要，
不读取设备内存。模型采用串行扇区 I/O 的 flush/FUA 语义。
[Linux 块设备缓存语义](https://docs.kernel.org/block/writeback_cache_control.html)。

| 场景 | 恢复结果 |
| --- | --- |
| 普通写后提前确认 | 扇区 0 确认留存，镜像缺该写，对账检出丢失 |
| FLUSH 后确认 | 扇区 0 保留，未同步的尾部扇区 1 丢失 |
| FUA 后确认 | 扇区 0 保留 FUA 内容，同扇区的旧缓存写及未同步的尾部扇区 1 丢失 |

证据限于设备模型与对账器校验。模型当前只在操作边界切断，未覆盖撕裂写、
同步过程中落盘的子集、乱序并发 I/O 或底层缓存误报。候选接入需要单独记录
存储引擎的实际 I/O 与客户端确认，并重开恢复其真实数据库。生产任务9还须
验证候选确认历史，涉及 Raft 日志、成员状态和业务数据。
