## 格式和权威边界

SQLite WAL 使用 `synchronous=FULL`，macOS 同时启用 `fullfsync`。打开时独占目录，
并校验版本 1、共识集群 ID 和节点 ID。多数派日志同步且应用后确认写入。读屏障
要求当前任期的多数派确认及日志应用。快照封套版本 1 包含 SHA-256、应用索引、
成员和业务状态。截断等待快照持久发布。原生备份格式 1 独立于 Raft 快照，恢复时
建立新的共识身份，旧租约失效并且旧 watch 需重新快照。
[OpenRaft 存储契约](https://docs.rs/openraft/0.9.22/openraft/storage/trait.RaftLogStorage.html)、
[SQLite 同步设置](https://sqlite.org/pragma.html#pragma_synchronous)、
[恢复回执](task-30.md)。

只有 leader 依据单调时间发起租约时钟推进，实际截止由提交顺序决定。失去 quorum
或切主时，未提交时间可能延后租约到期。删除和栅栏只读取已应用状态。可串行化读
显式允许陈旧本地视图。宿主负责提供认证、节点身份绑定和取消边界。loopback 测试
协议只用于本地三节点，版本间互操作尚待验证。
[适配器边界](../../../pkg/storage/kv/native.rs.md)、
[原生状态机](../../../pkg/storage/kv/native_state.rs.md)。

本地门槛沿用冻结 etcd 的 37.879 ms 写入 p99、16.618 ms 线性读对 p99、
73.580 事务/秒和 418.032 ms 同配置重启首读。三轮各恢复 128 笔、256 个键，
确认丢失为零。长稳另有预设 24 小时窗口和有限资源检查。
[本地长稳](soak.md)。

任一确认丢失、少数派确认线性操作、快照损坏静默通过或 fencing 错误均撤销本地通过
判定。主题 9 全量交付、生产节点认证和受控成员管理、混合版本及升级窗口、发布平台
和部署 SLO 继续作为上线门槛。
