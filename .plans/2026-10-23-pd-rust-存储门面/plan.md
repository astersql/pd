# PD Rust 存储门面计划

目标：将存储门面拆成单一验证故事的小任务，依赖满足后可在独立会话实施。

范围：组合 KV/endpoint、区域源切换与加载状态的 facade。

范围外：不选本地数据库，不实现 hot-region 历史存储、加密或 durability。

假设：规划基准 `5d5948052a9ee9e3fa7a09145fe2916a2912c223`；已有 storage/member/id/core/runtime 基线，外部 etcd 仍为过渡后端。新增文件、crate 和测试均为拟建，不代表已经存在。

## 设计决策

- 比较继续聚合与按包拆 crate；选择后者。MetaStore 只下沉到 kv 一次，storage 重导出；领域接口隔离协议。
- 比较按文件整包移植与按行为实现，选择按行为；测试先固定 Go 行为再实现。

## 架构说明

- `storage → endpoint → kv`；`member → election → kv`；keypath 独立，ID 复用 member；协议只进编码适配器。
- 宿主负责 runtime/取消/环境，禁止全局集群 ID、私有 runtime 与第二套 MetaStore。

## 来源与边界

- 来源：[主题 3](../2026-10-22-pd-rust-渐进迁移主题/3-迁移存储选主与配置契约.md)。来源史诗和上层 `plan.md` 保持原样；本次只生成计划。
- 前置独立计划：[存储端点](../2026-10-23-pd-rust-存储端点/prompt.md)。编号任务同时列出准确批次依赖；独立指文档和验收自包含，不表示可以跳过业务依赖。
- 各包只迁移本主题需要的纯值与存储行为。etcd 集群管理、完整 MCS、加密、本地持久化、PersistOptions 和启动装配属于上层主题，不能以当前子计划完成宣称整个 Go 包迁移完成。
- 完整 Config 仍依赖尚未迁移的调度等嵌套配置；相关任务有显式准入门。前置缺失时标为 `已阻塞`，不得以透传 JSON 或恒成功校验替代。

## 开发策略

- 对行为变更采用失败验证、通过验证、再重构；生产测试置于独立 `*_test.rs` 并显式注册。
- 所有批次全局串行；本计划与其余九个计划共用一条顺序。这样避免根 manifest、Cargo.lock、模块注册、workspace 格式化和 Go failpoint 改写冲突；没有可并行批次。
- 详细执行顺序、批次、文件占用和任务依赖只保存在编号文件及 `prompt.md`，本文件不记录进度，生成后只读。
- Go 源码和现有测试作为 oracle，不修改生产 Go 实现。先运行已有测试，再逐场景记录源码符号、断言、输入与期望；源码推导与实际跨语言运行差分必须分别标明。
- 字节编码任务需要真实 Go 编码输出：允许新增窄 `scripts/rust-theme3-oracle/` Go 测试工具，不修改已有 Go 生产包。每个任务只增加自己场景；工具不得进入 Rust 生产产物。纯源内确定值可记录推导，但不能冒充运行差分。
- root/workspace 新依赖统一精确锁定；已有依赖优先复用。crate 默认 features、无额外 feature，禁止为本计划添加推测开关。
- fixture 复用现有 `scripts/rust-etcd-fixture`：随机 loopback 端口、独立数据目录、同 WAL 重启。共享 helper 的迁移只有 KV 归属整理任务执行，后续调用而不复制。
- Go oracle 只能串行通过 `make gotest` 运行，结束/失败/中断确认 failpoint 已禁用；启用期间不编辑、不运行 Cargo 或非测试命令。跨计划另有活动会话时协调源码及格式化窗口。
- 文档任务不调用 Cargo。Rust 任务使用编号文件完整槽位契约；有实现变更获得证据后按 `$git-commit` 仅提交本任务变更。
- 任何任务完成依赖本轮证据，新增测试至少命中一例；内存与 etcd 共用断言。不存在编译成功、零测试、mock 调用次数或忽略测试即可验收的路径。
- 主题闭环须覆盖十个子计划全部已准入范围、已记录跨后端/重启/选主/配置差分，并重新盘点基准后的 Go 变化；缺少外部配置依赖时不得关闭来源史诗。
