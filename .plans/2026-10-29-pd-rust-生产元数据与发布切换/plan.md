# 生产元数据与发布切换计划

目标：将主题 10 拆为有决策门槛、可逐项验收的生产 MetaStore 与发布切换任务。

范围：候选比较、持久化和共识故障原型、生产读写事务、revision/watch/lease/fencing、成员变更、备份恢复、服务装配、混合版本、滚动升级、性能容量、长稳及三个独立切换方向的回滚证据。

范围外：实现完整 etcd API、修改 Go 源码或模块、Go FFI、跨仓库装配 SQL 服务、直接操作生产集群、恢复已淘汰组合。

假设：原主题 9 文件仍为未开始；当前存在用户未提交 Rust 修改。MetaStore 定义由 storage/domain 承载，kv 包提供适配；原任务中的根目录契约路径已过时。后端、格式及生产阈值尚未选定。

## 设计决策

- 成熟嵌入式组件减少共识实现风险；窄语义自研增加恢复证明成本；外部 etcd 保留基线但不满足最终目标。最终技术选型由故障证据决定，不预选引擎。
- 淘汰的是 MemStorage 加全量镜像组合，不是 Raft 算法。

## 架构说明

- domain 保持后端无关；kv 承载适配，storage 重导出，runtime 注入 MetaStore，bin 管进程。
- 原型不接生产工厂；三个切换方向分别验收。没有耐久性证据就保留 etcd。

## 开发策略

- 对行为变更使用失败验证、通过验证、重构；先记录 Go oracle，再实现 Rust。
- 先读取任务文件中的前置产物与准入要求；计划列出的新增文件和测试名是拟建交付物，不代表已存在。
- 候选提案不等于接受 ADR。原型证据不足或被淘汰时停止后续生产任务；禁止为赶进度把失败降级为不支持。
- 实验后若需更换候选或改变任务边界，先向用户说明并确认是否记录回来源产物，再新建修订计划；本 plan.md 生成后只读，原主题文件保持不变。
- 每次实现限制于一个行为；生产候选必须复用已经验证的组件，不能在单个任务内重新发明共识或存储引擎。
- 所有任务按编号线性执行，每批次一项。共用 kv 模块注册、锁文件、全 workspace 检查和集成环境，当前不安排并行；Cargo 分槽不解除源码或验证资源互斥。
- 编号任务记录状态，prompt.md 只提供执行提示。每个任务的持久证据保存到 docs/rust/production-meta/task-NN.md，完成后删除任务文件不会丢失验收记录。
- 新生产 Rust 源文件带版权、对应 .rs.md 说明；依照仓库既有说明组织，不凭空创建不存在的 manifest 约定。

## Go 只读硬约束

- Go 仅供只读参考。禁止新增、修改、删除、重命名任何 `.go` 文件（含生产代码、测试、oracle、生成文件及临时目录中的 Go 工具）；`go.mod`、`go.sum`、`go.work`、`go.work.sum` 同样只读。所有新增实现与测试使用 Rust，必要的非 Go 验证脚本和证据文档须在任务范围内。
- 禁止通过生成器、格式化、依赖整理、failpoint 注入或构建脚本间接改写 Go；不得运行会改写 Go 的 make 测试入口、failpoint 启停命令、`go generate`、`go mod tidy` 或 Go 格式化写入命令。不得以“只增加测试/工具”“临时修改后还原”或扩大任务范围绕过约束。
- Go oracle 仅复用已有只读源码、测试、fixtures、已保存输出或已有二进制；运行已有 Go 工具/测试前，必须确认整个调用链不写上述文件且不需要 failpoint 注入。需要 failpoint 的测试不得直接裸跑来替代验证；无法只读取得必要运行证据时，记录具体缺口并按任务阻塞规则处理，不降低验收标准，不将源码推导冒充运行差分。
- 开始与结束时核对上述文件的 Git 状态及内容，保留用户已有变更；本任务不得产生任何 Go 文件或 Go 模块文件差异。本约束优先于计划、执行技能或验证要求中任何相冲突的写入指令。
